Change Role & Deactivate Services

Managing user status and permissions requires strict safety rules to prevent administrative lockouts or unauthorized privilege escalation.

Core Logic

Endpoints in src/controllers/userController.js handle user deactivation and role updates. These operations use a per-tenant mutex (withTenantLock) to serialize requests, ensuring that "last-admin" checks are race-condition safe.

// src/controllers/userController.js

const tenantLocks = new Map();

function withTenantLock(tenantId, task) {
  const key = String(tenantId);
  const previous = tenantLocks.get(key) || Promise.resolve();
  const run = previous.then(() => task());
  // ... mutex implementation ...
  return run;
}

Security Rules

  • Self-Protection: Users cannot deactivate or demote themselves.
  • Privilege Gap Check: Users cannot assign a role with higher permissions than they currently hold, nor modify a user who holds permissions they lack.
  • Last-Admin Rule: Deactivation or demotion of the last active admin (USER_MANAGE) is blocked with a 409 error.

Refresh Token Revocation

On deactivation or role change, refreshTokenHash is set to null. This forces the user to log in again with their new effective permissions. While the existing access token (up to 15 minutes) remains valid, the user cannot acquire a new one.

// src/controllers/userController.js

target.isActive = false;
target.refreshTokenHash = null;
await target.save();
