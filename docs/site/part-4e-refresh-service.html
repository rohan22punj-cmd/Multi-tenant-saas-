4e Refresh Service & Token Rotation

This page explains the refresh() and logout() functions within src/services/authService.js, focusing on refresh token verification, token hashing, rotation, and reuse detection.

refresh() function in src/services/authService.js

The refresh function handles token renewal using a refresh token. It implements token rotation with reuse detection, ensuring that if an old (already-rotated) token is replayed, all user sessions are killed as a safety measure.

Source: src/services/authService.js

export async function refresh(refreshToken) {
  const GENERIC_MSG = 'Invalid refresh token';

  // 1. Verify signature and expiry
  let decoded;
  try {
    decoded = verifyRefreshToken(refreshToken);
  } catch {
    throw new AppError(GENERIC_MSG, 401);
  }

  // 2. Find the user and check tenant INSIDE tenant context
  // Context is set manually here using tenantId from the verified token payload —
  // there's no logged-in request yet (access token expired).
  const { userId, tenantId } = decoded;

  const user = await runWithTenant({ tenantId }, async () => {
    return User.findById(userId);
  });
  if (!user || !user.isActive) {
    throw new AppError(GENERIC_MSG, 401);
  }

  // 3. Check that the tenant still exists (unscoped - Tenant model)
  const tenant = await runUnscoped(
    'refresh: verify tenant still exists',
    () => Tenant.findById(tenantId)
  );
  if (!tenant) {
    throw new AppError(GENERIC_MSG, 401);
  }

  // 4. Hash the incoming token and compare with stored hash (inside tenant context)
  const incomingHash = hashToken(refreshToken);

  if (user.refreshTokenHash !== incomingHash) {
    // REUSE DETECTED — an old (already-rotated) token is being replayed.
    // Wipe the stored hash so even the newest token stops working.
    // This is the safety measure: if an attacker stole the old token,
    // nuking everything forces the real user to re-login (annoying but safe).
    await runWithTenant({ tenantId }, async () => {
      user.refreshTokenHash = null;
      await user.save();
    });
    throw new AppError(GENERIC_MSG, 401);
  }

  // 5. Fetch the role to get current permissions (inside tenant context)
  const role = await runWithTenant({ tenantId }, async () => {
    return Role.findById(user.roleId).lean();
  });
  if (!role) {
    throw new AppError(GENERIC_MSG, 401);
  }

  // 6. Issue fresh tokens (this also replaces the stored hash) inside tenant context
  const tokens = await runWithTenant({ tenantId }, async () => {
    return issueAndStoreTokens(user, role.permissions);
  });

  return tokens;
}

Line-by-line Explanation:

  1. const GENERIC_MSG = 'Invalid refresh token';: Defines a generic error message used for all refresh failures to prevent leaking information about why a token was rejected.
  2. let decoded; try { decoded = verifyRefreshToken(refreshToken); } catch { throw new AppError(GENERIC_MSG, 401); }: Refresh Token Verification (refreshSecret). The incoming refresh token is verified using verifyRefreshToken, which checks the token's signature (using the refreshSecret configured in config/env.js) and its expiry. If verification fails, a generic "Invalid refresh token" error is thrown.
  3. const { userId, tenantId } = decoded;: Extracts the userId and tenantId from the decoded (verified) token payload.
  4. const user = await runWithTenant({ tenantId }, async () => { return User.findById(userId); });: Looks up the user within the tenant's context. The context is established using the tenantId extracted from the verified token, ensuring the user lookup is scoped to the correct tenant.
  5. const tenant = await runUnscoped('refresh: verify tenant still exists', () => Tenant.findById(tenantId));: Verifies the tenant still exists. The runUnscoped wrapper is used because the Tenant model is not tenant-scoped (it's the top level of the hierarchy).
  6. const incomingHash = hashToken(refreshToken);: Token Hashing (SHA-256). The incoming refresh token is hashed using the hashToken helper function, which computes a SHA-256 digest. This hash is then compared against the stored hash in the database.
  7. if (user.refreshTokenHash !== incomingHash) { ... user.refreshTokenHash = null; ... throw new AppError(GENERIC_MSG, 401); }: Token Rotation & Reuse Detection. If the incoming hash does not match the stored hash, it means an old (already-rotated) token is being replayed. As a safety measure, the stored refreshTokenHash is cleared to null, which kills all sessions for that user (they'll need to re-login). This prevents replay attacks even if an attacker has stolen an old token.
  8. const role = await runWithTenant({ tenantId }, async () => { return Role.findById(user.roleId).lean(); });: Fetches the user's role and associated permissions within the tenant context.
  9. const tokens = await runWithTenant({ tenantId }, async () => { return issueAndStoreTokens(user, role.permissions); });: Issues fresh access and refresh tokens, and replaces the stored hash (rotation).
  10. return tokens;: Returns the newly issued tokens.

logout() function in src/services/authService.js

The logout function invalidates the refresh token by clearing the stored hash. It always succeeds, regardless of whether the token is valid.

Source: src/services/authService.js

export async function logout(refreshToken) {
  // Best-effort: try to decode the token to find the user.
  // If it's garbage or expired, we just do nothing — still return success.
  try {
    const decoded = verifyRefreshToken(refreshToken);
    const { userId, tenantId } = decoded;

    // Run inside tenant context using tenantId from the verified token
    // Context is set manually here because there's no logged-in request.
    await runWithTenant({ tenantId }, async () => {
      await User.findByIdAndUpdate(userId, { refreshTokenHash: null });
    });
  } catch {
    // Token is garbage or expired — nothing to clear, that's fine.
  }
}

Line-by-line Explanation:

  1. export async function logout(refreshToken) {: Defines the asynchronous logout function, accepting a refreshToken argument.
  2. try { const decoded = verifyRefreshToken(refreshToken); ... }: Attempts to decode and verify the refresh token (signature and expiry check, again using the refreshSecret).
  3. const { userId, tenantId } = decoded;: Extracts the userId and tenantId from the decoded token payload.
  4. await runWithTenant({ tenantId }, async () => { await User.findByIdAndUpdate(userId, { refreshTokenHash: null }); });: Runs inside the tenant context, and updates the user, setting refreshTokenHash to null. This invalidates the refresh token so it can never be reused.
  5. } catch { /* Token is garbage or expired — nothing to clear, that's fine. */ }: If the token is garbage or expired, verification fails and we do nothing — the function still returns success, since logout should never show an error to the user.

Token Hashing & Reuse Detection

Refresh tokens are never stored in raw form — only their SHA-256 hash (via hashToken) is persisted. On every refresh, the stored hash is replaced (rotation). If an old token is detected, the hash is wiped entirely, killing all user sessions as a safety measure.

Separate Access & Refresh Secrets

Access tokens and refresh tokens use separate secrets configured in config/env.js (ACCESS_SECRET and REFRESH_SECRET). This ensures that even if one secret is compromised, the other type of token remains secure.
