    Part 4f: Invite & Accept-Invite Services (src/controllers/authController.js)

    src/controllers/authController.js

    The invite function handles creation of invite links. The acceptInvite function handles redemption of invite tokens. Both enforce security rules such as privilege checks and generic error messages.

    const tokenHash = crypto.createHash('sha256').update(token).digest('hex');

const result = await runWithTenant({ tenantId: tenant._id }, async () => {
  const invite = await Invite.findOneAndUpdate(
    { tokenHash, acceptedAt: null, expiresAt: { $gt: new Date() } },
    { acceptedAt: new Date() },
    { new: true }
  );

  if (!invite) {
    throw new AppError('Invalid or expired invite', 400);
  }

  // ... create user, hash password, issue tokens ...
});

    Explanation:

    • Invite token hashing: The invite token is hashed using SHA-256 (hashToken or createHash('sha256')) before being stored in the database, ensuring the raw token is never stored.
    • Privilege rule check: The invite function checks that the inviter has all permissions required by the target role. If not, it returns a 403 Forbidden error.
    • Atomic invite acceptance: The findOneAndUpdate with acceptedAt: null and expiresAt: { $gt: new Date() } filter ensures only unexpired, unaccepted invites can be accepted, and only one request can claim them (atomic).
    • Generic error message: On accept failure, the same generic "Invalid or expired invite" error is returned for all failure cases, preventing information leakage.
