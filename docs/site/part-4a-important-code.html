Multi-Tenant SaaS Walkthrough

    Part 4a: Important Code (tenantContext.js & protect.js)

    src/utils/tenantContext.js

    This file provides a way to automatically associate a tenant ID (and user ID) with every incoming HTTP request, without having to pass it through every function argument manually. It leverages Node.js's AsyncLocalStorage for this purpose, ensuring per-request tenant isolation.

    import { AsyncLocalStorage } from 'node:async_hooks';
import logger from '../config/logger.js';

const asyncLocalStorage = new AsyncLocalStorage();

// Internal flag to track when we're intentionally running unscoped
let unscopedDepth = 0;

/**
 * Runs the given callback inside an async context that carries
 * the provided context object (tenantId, userId, …). Typically
 * called by middleware.
 *
 * @param {Object} context - e.g. { tenantId, userId }
 * @param {Function} callback - the rest of the request handling
 */
export function runWithTenant(context, callback) {
  return asyncLocalStorage.run(context, callback);
}

/**
 * Reads the tenantId stored by runWithTenant for the current
 * request. THROWS if called outside a tenant context.
 * This prevents silent undefined bugs that leak data.
 */
export function getTenantId() {
  if (unscopedDepth > 0) {
    // Inside runUnscoped — return undefined so the plugin knows
    // not to apply a filter. The plugin checks isUnscoped() instead.
    return undefined;
  }
  const store = asyncLocalStorage.getStore();
  if (!store?.tenantId) {
    throw new Error(
      'getTenantId() called outside a tenant context. ' +
      'Ensure the request passed through protect + tenantContext middleware.'
    );
  }
  return store.tenantId;
}

/**
 * Returns the full context object (tenantId, userId, …) for the
 * current request. Returns undefined if inside runUnscoped.
 * Throws if no context is set and not unscoped.
 */
export function getContext() {
  if (unscopedDepth > 0) {
    return undefined;
  }
  const store = asyncLocalStorage.getStore();
  if (!store) {
    throw new Error(
      'getContext() called outside a tenant context.'
    );
  }
  return store;
}

/**
 * Checks if we are currently inside a runUnscoped block.
 * Used by the tenant plugin to skip tenant filtering.
 */
export function isUnscoped() {
  return unscopedDepth > 0;
}

/**
 * ESCAPE HATCH — runs a callback WITHOUT any tenant filter.
 *
 * WHAT THIS DOES:
 * Temporarily disables the tenant context so Mongoose queries run
 * unfiltered (see ALL tenants' data). This is DANGEROUS and should
 * only be used for:
 *   - System-level operations (migrations, seeding, cron jobs)
 *   - Cross-tenant analytics/reporting (with strict access control)
 *   - Operations on the Tenant model itself (which has no tenantId)
 *
 * WHY IT EXISTS:
 * The Tenant model has no tenantId — it IS the tenant. Creating or
 * looking up tenants by slug must run unscoped. A few other rare
 * system cases also need it.
 *
 * SAFETY MEASURES:
 * - reason (string) is REQUIRED — forces the developer to justify it
 * - Logs a WARNING with the reason so every usage is auditable
 * - Single function name (runUnscoped) makes it trivial to grep:
 *     grep -r "runUnscoped" src/
 * - Nesting is tracked so nested calls work correctly
 *
 * @param {string} reason - REQUIRED human-readable justification
 * @param {Function} callback - async function to run unscoped
 * @returns {Promise<*>} - whatever the callback returns
 */
export async function runUnscoped(reason, callback) {
  if (!reason || typeof reason !== 'string' || !reason.trim()) {
    throw new Error('runUnscoped() requires a non-empty reason string');
  }

  unscopedDepth++;
  logger.warn({ reason, unscopedDepth }, 'runUnscoped: executing without tenant filter');

  try {
    // Run with an empty store (no tenantId) — getTenantId will return undefined
    return await asyncLocalStorage.run({}, callback);
  } finally {
    unscopedDepth--;
  }
}

export default asyncLocalStorage;

    Explanation of tenantContext.js:

    • AsyncLocalStorage: This is a built-in Node.js API that allows you to store data during the lifetime of an asynchronous operation (like an HTTP request) and retrieve it at any point within that operation's execution flow. It's crucial for multitenancy because it avoids passing tenantId through every function call.
    • runWithTenant(context, callback): This function takes a context object (containing tenantId and userId) and a callback. It executes the callback within a new async context where the provided context is available. This is typically called by the authentication middleware (protect.js) once the tenant is identified.
    • getTenantId(): This function retrieves the tenantId from the current async context.
      Why it throws instead of returning undefined: If getTenantId() were to return undefined when no tenant context is set, it could lead to silent data leaks where a query accidentally runs unscoped across all tenants. By throwing an error, the system immediately alerts developers to a missing tenant context, preventing critical security vulnerabilities. When intentionally running unscoped (via runUnscoped), it returns undefined, which the Mongoose plugin interprets as a signal to skip tenant filtering.
    • runUnscoped(reason, callback): This is an "escape hatch" function that temporarily disables tenant filtering for the code executed within its callback. This is a powerful and potentially dangerous operation, as it allows access to data across all tenants.
      Required reason: To mitigate the risks, a reason string is mandatory. This forces developers to explicitly justify why an unscoped operation is necessary and provides an audit trail in the logs. It's used for system-level tasks (migrations, seeding), cross-tenant reporting, or operations on the Tenant model itself.
    • unscopedDepth and isUnscoped(): These are used internally to track when runUnscoped is active, allowing for correct nesting of unscoped calls.

    src/middleware/protect.js

    This middleware is responsible for authenticating incoming requests and establishing the tenant context. It ensures that only authenticated users with valid tokens can access protected routes and sets up the environment for tenant isolation.

    import { verifyAccessToken } from '../utils/tokens.js';
import AppError from '../utils/AppError.js';
import { runWithTenant } from '../utils/tenantContext.js';

const UNAUTHORIZED = 'Unauthorized';

const protect = async (req, _res, next) => {
  // 1. Extract the token from the Authorization header
  const authHeader = req.headers.authorization;
  if (!authHeader || !authHeader.startsWith('Bearer ')) {
    throw new AppError(UNAUTHORIZED, 401);
  }

  const token = authHeader.split(' ')[1];

  // 2. Verify signature + expiry (access secret)
  let decoded;
  try {
    decoded = verifyAccessToken(token);
  } catch {
    throw new AppError(UNAUTHORIZED, 401);
  }

  // 3. Build req.user from token payload (no DB lookup)
  req.user = {
    userId: decoded.userId,
    tenantId: decoded.tenantId,
    roleId: decoded.roleId,
    permissions: decoded.permissions || [],
  };

  // 4. Run downstream inside async tenant context
  runWithTenant(
    { tenantId: decoded.tenantId, userId: decoded.userId },
    () => next()
  );
};

export default protect;

    Explanation of protect.js:

    • Line 31-36 (Authorization header parsing): It extracts the JWT from the Authorization header, expecting the format "Bearer ". If the header is missing or malformed, it throws an AppError with a 401 Unauthorized status.
    • Line 39-44 (JWT access token verification): The extracted token is then verified using verifyAccessToken. This function checks the JWT's signature (ensuring it hasn't been tampered with) and its expiration date. If verification fails (e.g., invalid signature, expired token), it throws a 401 Unauthorized error.
    • Line 47-52 (Extracting tenantId/userId/permissions): Upon successful verification, the payload of the JWT (decoded) is used to populate req.user. This includes userId, tenantId, roleId, and permissions. Critically, this step involves no database lookups, making it very fast. The trade-off is that user role/permission changes in the database won't take effect until the access token expires (typically 15 minutes) and a new one is issued.
    • Line 55-58 (Setting AsyncLocalStorage context via runWithTenant): The core of tenant isolation. The tenantId and userId extracted from the token are passed to runWithTenant from tenantContext.js. This ensures that all subsequent code execution within the request (controllers, services, Mongoose plugins) automatically has access to the correct tenant context without explicit passing. The next() Express middleware function is called inside this context, allowing the request to proceed to the next handler.
